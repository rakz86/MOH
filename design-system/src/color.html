Semantic roles

This is the layer components actually consume. A role says what a colour is for, which is why the same component works unchanged in light and dark.

Surfaces
canvas
The page ground. Never white — white is for raised content.
surface
Cards, tables, inputs. Sits above the canvas.
surface-sunken
Table headers, addons, footers of panels.
surface-inverse
Government bar and site footer.
Text
text
Body and headings. 17.15:1 on surface.
text-secondary
Supporting copy, table headers, hints.
text-muted
Placeholders and timestamps. 4.50:1 — do not go lighter.
text-link
Links and primary text actions.
Borders
border
Decorative dividers and card edges. No contrast floor.
border-strong
Emphasis dividers. Still decorative.
border-control
Interactive control boundaries. Must hold 3:1 — WCAG 1.4.11.
Action
primary
The single action that advances the task.
primary-wash
Hover ground, selected rows, quiet emphasis.
accent
RESTRICTED — 3.10:1 on white. Large text, graphics and dark surfaces only. Never body copy.
focus
The focus ring. One treatment system-wide, never removed.

Request lifecycle colour

Seven states, each with a reserved hue, a distinct shape, and a word. Switch this page to dark and the same seven stay legible — the dark theme uses its own ramp rather than an inverted light one.

Draft Submitted In review Action required Approved Rejected Fulfilled

Never reassign these hues. Green means approved and only approved. If a new state is needed, it takes a new shape and a new word before it takes a new colour — and it must survive the greyscale test: print the page in black and white and every state must still be distinguishable.
